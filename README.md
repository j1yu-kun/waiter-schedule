# График официантов — первая версия

Сайт для GitHub Pages и Supabase. Архив содержит index.html, style.css, script.js, config.js и schema.sql. Нужны интернет и собственный проект Supabase.

## 1. Создайте Supabase

1. Зайдите на https://supabase.com/ и создайте проект.
2. Откройте SQL Editor, создайте запрос, вставьте содержимое `schema.sql` целиком и выполните. Это создаст таблицы, правила доступа и функцию публикации. Схема рассчитана на новый пустой проект; не запускайте повторно в проекте с такими же таблицами.
3. В настройках проекта найдите Project URL и publishable key (или legacy anon key). Вставьте в `config.js`. Эти значения предназначены для браузера. **Никогда не вставляйте secret key, service_role key или пароль базы в код сайта или GitHub.**

## 2. Создайте аккаунты

1. В Supabase откройте Authentication → Users → Add user / Create new user. Создайте свой аккаунт с электронной почтой и паролем. Подтвердите email в настройках создания пользователя, если предлагается.
2. Откройте Table Editor → profiles и создайте строку: `id` — UUID созданного пользователя из Authentication, `name` — ваше имя, `role` — `admin`.
3. Так же создайте аккаунты сотрудников и строки в profiles с `role = staff`. Аккаунт без строки profiles не сможет пользоваться сайтом. Передавайте каждому пароль лично, не выкладывайте его в GitHub.
4. Роли задаются администратором через Supabase. На сайте нельзя самостоятельно назначить себе администратора.

## 3. Локальный запуск и GitHub Pages

Откройте папку в VS Code. Для локальной проверки используйте расширение Live Server либо любой локальный статический сервер. Откройте страницу, войдите и создайте период. Для публикации загрузите файлы проекта в GitHub-репозиторий и в Settings → Pages выберите Deploy from a branch, ветку main и папку / (root). Дождитесь адреса Pages.

## Как пользоваться

Администратор создаёт непересекающиеся периоды, указывая название, например «Ноябрь 1/2». Сотрудники заполняют каждый день и нажимают «Сохранить доступность». После этого администратор составляет черновик, кликает ячейки для исправления и публикует. Опубликованный график виден вошедшим пользователям. Каждая публикация сохраняет отдельную версию: администратор выбирает предыдущую версию на вкладке «График». Чтобы изменить актуальный график, нажмите «Изменить актуальный график», внесите правки и опубликуйте новую версию. На вкладках «Мои смены» и «Общий график» показаны только утверждённые смены. До публикации черновик хранится только в открытой вкладке: при смене периода или обновлении страницы он пропадёт.

## Правила и ограничения версии

- Понедельник–воскресенье: максимум 5 назначенных дней. Для редкого исключения 6 дней администратор может вручную назначить смену и опубликовать график, подтвердив предупреждение.
- После вечера и полного дня нельзя назначить утро или полный день на следующий день. Смена «д» допустима на следующий день. Проверяются данные опубликованного графика соседних периодов. Если прежний период не загружен в систему, администратору нужно вручную проверить границу периода.
- День и полный день учитываются по одному человеку для утра и вечера. Время внутри смен отдельно не контролируется.
- Утро + вечер в доступности разрешает каждую из этих смен и полный день. Дневная смена — отдельный выбор. При отсутствии отметки день не считается доступным.
- Алгоритм эвристический, не гарантирует нахождения лучшего или полного графика. Возможна нехватка даже при существовании решения; редактируйте вручную и проверяйте. Особые требования к людям, праздничные нормативы и гибкие настройки потребности пока не реализованы. Пересоздание черновика не учитывает предыдущие ручные изменения.
- Нормативы: будни 4/4, суббота и воскресенье 5/4. Встроенный календарь не учитывает праздничные переносы.
- Редактирование и публикация с предупреждениями разрешены только администратору. Обязательно проверяйте график и редкие исключения. Список имён и опубликованный график видны всем авторизованным сотрудникам.
- На бесплатном Supabase проект может быть приостановлен при неактивности. Настройте резервное копирование и следите за доступом к аккаунту.

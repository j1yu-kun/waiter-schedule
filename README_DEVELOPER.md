# Детский сад 2.0 — структура клиентской части

## Установка

Сохраните копию текущего проекта. Замените **вместе** `index.html`, `script.js` и `style.css` файлами из этого каталога. Существующий `config.js` оставьте рядом с ними: в архив он не включён. Обновите страницу с очисткой кеша (Ctrl+F5).

SQL для этого обновления не нужен. Здесь изменены интерфейс и клиентская последовательность публикации; серверные функции Supabase остаются существующими. Файлы не опубликованы на GitHub.

## Где что находится

| Файл                       | Назначение                                                                 |
| -------------------------- | -------------------------------------------------------------------------- |
| `index.html`               | Экраны входа, главная, админка, формы и HTML-шаблоны повторяемых элементов |
| `script.js`                | Состояние приложения, запросы к Supabase, обработчики, заполнение шаблонов |
| `style.css`                | Общие стили, компоненты и адаптация под размер экрана                      |
| `config.js` (существующий) | `window.APP_CONFIG` с настройками подключения                              |
| `.editorconfig`            | Табуляция, LF, UTF-8 и завершающая новая строка                            |
| `.prettierrc.json`         | Единые параметры автоматического форматирования                            |

## Разметка и данные

Постоянные панели находятся непосредственно в `index.html`. Повторяемые строки графика, задачи, карточки смен и варианты списков вынесены в конец этого файла в блоки `<script type="text/html" id="tpl-...">`.

Эти блоки **не исполняют JavaScript**. Они хранят HTML как текст: это позволяет сохранять отдельные `<tr>`, `<td>` и `<option>` без исправлений браузерным HTML-парсером. В комментариях перед шаблонами перечислены их параметры.

Функция `renderTemplate(id, values)` в начале `script.js` читает шаблон и подставляет поля `{{name}}`. Например, чтобы изменить внешний вид строки задачи, найдите вызываемый в соответствующей функции `tpl-...` и отредактируйте его в HTML.

Пользовательские значения перед вставкой в HTML должны проходить через существующие `esc`, `safe` или `escape`. Сам `renderTemplate` не экранирует значения, поскольку некоторые параметры содержат вложенные шаблоны. Не передавайте в них необработанный пользовательский HTML. Подстановка выполняется один раз: похожие на параметры символы внутри имени не интерпретируются повторно.

## Основные блоки JavaScript

1. Шаблоны, общие переменные, даты и уведомления.
2. Расчёт черновика, пожелания, таблицы и загрузка выбранного периода.
3. Авторизация, профили, заявки регистрации и обработчики админки.
4. Задачи на сегодня, ручное назначение и выполнение.
5. Справочник регулярных задач.
6. История задач и переназначение исполнителя.
7. Настройки зон и отображение сотрудников на смене.
8. Ручной обмен зонами.
9. Запуск `init()` после установки обработчиков.

Блоки справочника, истории и зон изолированы функциями-обёртками. Общие переменные `me`, `profiles`, `periods`, `assigned`, `versions` используются несколькими блоками. При изменении обработчиков проверьте связанные экраны.

Правила распределения задач и зон выполняются серверными RPC в Supabase. Перенос разметки не заменяет и не меняет эти правила.

## CSS и форматирование

В CSS есть разделы с комментариями. Дубли одинаковых селекторов объединены с сохранением итоговых значений, неиспользуемые старые правила раскладки удалены. Для новых компонентов используйте отдельные классы; перед добавлением правила найдите существующий селектор. Не наращивайте переопределения в конце файла.

Отступы — символ табуляции, визуальная ширина — 4. Настройки Prettier приложены. Для автоматического форматирования в редакторе нужен установленный Prettier; приложение само его не использует и сборки не требует.

## Интерфейс и навигация

- Период выбирается в карточке «График команды», рядом с версиями. Стрелки переключают соседние периоды. В админке есть синхронизированный выбор рабочего периода.
- Главные задачи и состав смены всегда относятся к сегодняшнему дню, даже при просмотре архивного графика.
- Админка разделена на «График», «Задачи», «Распределение зон». Заявки регистрации вынесены отдельно.
- Задачи сгруппированы по смене и выполнению. Состояние раскрытия сохраняется при обновлении данных в текущем сеансе страницы.
- Справочник редактируется в диалоге. Дополнительные задачи и история находятся в одной вкладке, без дублирования списка назначений.
- Календарь зон читает сохранённые назначения последней публикации соответствующего периода. Он не восстанавливает удалённые данные и не является журналом каждой ручной правки.
- Карточки сотрудников разделены на утро, вечер, полный день и дневную смену. Различающиеся зоны показаны двумя строками.

## Публикация и распределение

После `publish_schedule` клиент проверяет наличие задач и зон новой версии. Если соответствующих записей нет, вызывает `generate_tasks_for_version` / `generate_zones_for_version` с `p_version`. Это сохраняет совместимость с базой, где распределение уже выполняется триггерами, и не запускает повторную генерацию поверх созданных назначений.

При ошибке одного этапа появляется кнопка повторения незавершённых этапов. Она не публикует график заново. Состояние повторения хранится в памяти страницы; не закрывайте её до завершения операции. Наличие хотя бы одной записи считается признаком серверного распределения, поэтому эта проверка не выявляет частично заполненные данные. Последовательность клиентских RPC не является единой транзакцией: для полной атомарности потребуется отдельно объединить операции на сервере.

Тумблер летника вызывает существующий `set_period_terrace(p_period, p_enabled)`. Этот RPC сохраняет настройку и пересчитывает зоны; перед изменением опубликованного периода интерфейс предупреждает о возможной замене ручных назначений. Ручной обмен использует существующий `swap_employee_zones`.

События `portal:tasks-changed`, `portal:zones-changed`, `portal:data-changed` обновляют связанные панели. Навигация и календарь вынесены в отдельные блоки в конце JS перед `init()`.

## Что проверено

- Синтаксис JavaScript, параметры HTML-шаблонов и уникальность HTML ID.
- Вкладки, редактор задачи, выбор дней, сохранение, календарь и тумблер.
- Отметка выполнения сотрудником, счётчики и сохранение раскрытых групп.
- Публикация с готовыми серверными назначениями и повторение сбойного этапа без новой публикации.
- Экранирование специальных символов в именах и задачах.
- Экраны шириной 1280 и 390 пикселей, отсутствие горизонтального переполнения страницы.

Проверки выполнены в Chromium с локальными тестовыми ответами вместо Supabase. Реальная база и её права не проверялись. После замены файлов проверьте вход, переключение периода и версии, публикацию тестового графика, выполнение задач и ручной обмен зонами на вашей тестовой базе.
